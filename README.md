# 命の砂時計

まずローカルで制作・確認し、完成後に `munieru.app` のサブドメインへ配置するウェブアプリです。サブドメイン名・ホスティング先は未決定です。現在は未公開で、DNSの変更も行っていません。

## ローカルで起動

このフォルダで次を実行します。Node.js・npmとPython 3が必要です。パッケージのインストールは不要です。

```sh
npm run dev
```

ブラウザで http://127.0.0.1:4173/ を開きます。停止はターミナルで Ctrl+C を押します。別の端末からはアクセスできない設定です。

## 編集と確認

- `dist/index.html`：画面の構成と文言
- `dist/style.css`：デザインとレスポンシブ表示
- `dist/app.mjs`：設定とカウントダウンの操作
- `dist/time.mjs`：日付と残り時間の計算

編集後にブラウザを再読み込みすると反映されます。構文の確認は `npm run check` で実行します。`dist/` が配信可能な静的ファイル一式です。公開前に `npm ci` と `npm run build` を実行すると、画像・メタ情報・オフラインキャッシュのバージョンを更新できます。

## 公開の方針

候補URLは `inochi.munieru.app` などです。名前はまだ確定していません。

ローカル版を確認した後、利用するホスティング先を決め、`dist/` の配置とサブドメインのDNS・HTTPSを設定します。現時点で特定のホスティングサービスに依存する構成や、自動デプロイは設けていません。

以前Sitesに非公開・未デプロイのプロジェクト枠を登録しましたが、このローカル版はそれに接続していません。

## データと計算

生年月日・性別・寿命はブラウザのlocalStorageに保存します。アプリからサーバーへの送信は行いません。保存データはオリジンごとに分かれるため、ローカル版から公開版への自動引き継ぎはありません。

性別選択時に日本の2025年の平均寿命を自動入力します。元の統計値は男性81.35歳、女性87.33歳で、四捨五入した男性81歳・女性87歳を自動入力します。個人の寿命や現在年齢の平均余命の予測ではありません。寿命は1〜120歳の整数で入力し、その年齢の誕生日午前0時までを計算します。以前保存した小数の寿命は、読み込み時に四捨五入します。2月29日の誕生日は平年では2月28日として扱います。

日付計算の境界条件9項目、JavaScript構文、HTML要素参照、ローカルHTTP応答を確認済みです。実ブラウザでの画面・操作確認は環境制限により未実施です。

## 初回入力

初回は生年月日・性別・寿命を入力してから砂時計を表示します。性別は男性・女性から選択でき、寿命を自動入力します。自動入力後の手動変更も可能です。保存済みの設定に性別がない場合は再入力を案内し、既存の生年月日を保持します。データ削除後は初回画面に戻ります。

## レスポンシブ表示

スマートフォンを基準としたCSSです。600pxから補足情報を横並びに、900pxから初回の砂時計とフォームを横並びにします。スマートフォンの横向きには別の配置を用意し、画面のセーフエリア、可変の表示高さ、16px以上の入力文字、44px以上の操作領域を考慮しています。実機およびブラウザでの画面検証は未実施です。

平均寿命の出典：[厚生労働省・令和7（2025）年簡易生命表](https://www.mhlw.go.jp/toukei/saikin/hw/life/life25/index.html)。統計値はアプリに同梱し、性別選択によるサーバーへのデータ送信は行いません。

## アイコンとSNS共有画像

- `dist/favicon.svg` / `dist/favicon.ico`：砂時計のファビコン（ICOは16・32・48px）
- `dist/apple-touch-icon.png`：iPhone・iPadのホーム画面用（180px）
- `dist/site.webmanifest`：ホーム画面追加時のアプリ名とアイコン（192・512px、maskable対応）
- `dist/assets/og-icon.png`：正方形の砂時計アイコン（512px、OGPの代替画像）
- `dist/assets/og-banner.png`：ロゴA＋砂時計のSNSバナー（1200×630px、初期設定）
- `dist/assets/og-banner-logo-only.png`：ロゴAのみのSNSバナー（1200×630px）

採用したロゴ画像はそのまま合成し、砂時計アイコンはSVGから生成しています。すべて配信時に外部画像サービスへ依存しません。

再生成する場合だけ、開発依存をインストールして実行します。

```sh
npm ci
npm run assets
```

`site.config.json` の `origin` は現在 `http://127.0.0.1:4173` です。公開先が決まったらそのHTTPSオリジンに変更し、`npm run build` を実行してください。canonical・og:url・og:image・twitter:imageがまとめて更新されます。サブドメインのDNSやホスティングはこの操作では変更しません。

ロゴのみのバナーを採用する場合は同ファイルの `socialImage` を `assets/og-banner-logo-only.png` に変更して `npm run build` で再生成します。

SNSはローカルURLを読み取れません。実際の共有カードは、一般公開後に各サービスで確認してください。ホーム画面追加の表示・挙動も実機では未確認です。Service Workerで主要な画面・スクリプト・アイコンを保存し、キャッシュ完了後のオフライン起動に対応します。

## PWAとオフライン利用

- 初回アクセスで13個のアプリ用ファイルをキャッシュします。キャッシュ完了後はオフラインで砂時計・設定を利用できます。外部のXリンクや出典ページはオフライン対象外です。
- 対応ブラウザではページ上部に「アプリを追加」が表示されます。iPhone・iPadではSafariの共有メニューから「ホーム画面に追加」を利用します。ブラウザによりインストールの表示・可否は異なります。
- 公開環境ではHTTPSが必要です。開発用のlocalhost・127.0.0.1でもService Workerを登録できます。スマートフォンからMacのLAN内HTTPアドレスに接続するだけでは、PWAの動作条件を満たしません。
- 更新版が待機していると「更新する」が表示されます。押すと再読み込みします。設定は保存した状態で引き継ぎます。設定を削除せずに、バージョンごとのアプリキャッシュを入れ替えます。
- 公開環境は同じバージョンのHTML・JS・CSSをセットで使います。ローカル開発中はネットワークを優先し、接続できない場合は保存済みのバージョンを表示します。
- キャッシュするのは同一オリジンの明示した静的ファイルだけです。個人データをネットワークへ送る処理や、API・外部ページをキャッシュする処理はありません。
- ローカルで編集したら `npm run pwa`、公開準備では `npm run build` を実行します。`sw.js` のバージョンは対象ファイルから自動生成します。HTTP配信時は `sw.js` に長期キャッシュを指定しないでください。
- 単体HTMLをfile://で開く版ではPWAの登録を行いません。PWAの確認にはHTTPサーバー版を使います。

検証：`npm run check` と `npm test`。Service Workerのキャッシュ・オフライン応答・更新・インストールUIのロジックをテストしています。ブラウザ上でのService Workerの実動作とスマートフォンへのインストールは未検証です。

残り時間は日数・週数・月数・年数で表示します。日数は24時間、週数は7日単位です。月数・年数は今日から暦に沿って数え、端数を切り捨てます。月末は移動先の月の最終日に合わせます。各表示は独立した換算値です。

メインの残り時間は「年・ヶ月・日・時間・分・秒」に分解して表示します。年・月の合計月数を暦に沿って進め、残りを24時間単位の日・時・分・秒に分解します。下部の日数・週数・月数・年数は、それぞれ残り時間全体の換算値です。
